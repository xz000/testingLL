# 宽高比 4:3–21:9 动态布局规划（方案 2）

> 状态：**Phase A 已实施（`c741c6e`）**；Phase B/C 待做（2026-10-17）。
> 目标：窗口/全屏在 4:3–21:9 之间时**用满屏幕**，而不是固定 1280×720 外框 letterbox；宽屏显示更多横向场景，HUD 贴边。

## 0. 现状

- `client/src/ui.rs`：固定设计空间 `UI_W=1280 / UI_H=720`；`design_rect` 保持 16:9 并 letterbox；`mouse_design` 做逆变换。
- `client/src/main.rs`：`UI_W` 35 处、`UI_H` 34 处（多为 `(sw, sh) = (UI_W, UI_H)` 的面板/菜单/HUD）。
- 相机 `update_camera` 用 `base = min(UI_W, UI_H) * 0.45 / START_RADIUS`，并以 `UI_W/2, UI_H/2` 为中心。
- 窗口可拉伸，`Resized` 只做最小尺寸限制（640×360），布局本身不随比例变化。
- 当前非 16:9 正确但两侧/上下留黑边，**不会显示更多世界**。

## 1. 目标规则

- 设计高度固定 **720**；设计宽度 `sw = 720 × aspect`；
- `aspect` 限制在 **[4/3, 21/9]**（960–1680）；超出范围继续 letterbox；
- 窗口在范围内时：**无黑边、用满屏幕**；
- 相机按**高度**缩放（垂直视野恒定），宽屏自然显示更多横向场景；
- HUD/面板锚定真实左右边缘；窄屏时面板允许收缩/换行；
- 鼠标、命中盒、绘制坐标统一用动态 `sw/sh`。

## 2. 实施分期

### Phase A：UI 原语 + 相机 + 主菜单/Esc（约 1 天）

1. `ui.rs`
   - 保留 `UI_H=720`、`BASE_W=1280`（仅作参考/初始窗口）；
   - 新增 `view_aspect(ctx)`、`view_size(ctx) -> (sw, sh)`；
   - `design_rect` 改为“动态宽度 + 高度固定，比例外 letterbox”；
   - `mouse_design` 同步。
2. `update_camera`
   - `sw = view_w()`，`sh = 720`；
   - `base` 改为只按 `sh` 计算（不再 `min(sw, sh)`）；
   - 平移/缩放锚点、边界 clamp 使用动态 `sw`。
3. 主菜单/Esc/简单 HUD
   - `main_menu_card_w/rect` 接收动态 `sw`；
   - `escape_menu_rows`、顶部/底部横幅、等待横幅等改用 `view_size`。
4. 纯函数测试：960×720 / 1280×720 / 1680×720 下卡片居中、行不越界。

### Phase B：逐屏迁移（约 1–2 天）

按“最常看 → 最少看”的顺序：

1. 对局 HUD（血条、技能栏、分数、Kill feed、缩圈提示）；
2. 设置 / 训练场 / 键位；
3. Steam 大厅/房间/好友面板；
4. 结算/排行榜/成就；
5. Workshop/图标包；
6. 所有 `UI_W/UI_H` 剩余引用与布局测试。

每屏原则：

- 面板宽度用 `sw` 的百分比 + `min/max`，不再写死 1280 基准；
- 文本过长时允许换行/截断，避免 4:3 溢出；
- 双列/三列布局在窄屏可降为单列（必要时）。

### Phase C：设置与验收（约 0.5–1 天）

- 设置 → 显示：增加 **4:3 / 16:10 / 16:9 / 21:9** 预设（窗口可继续自由拉伸）；
- 全屏：沿用显示器比例；若超出 21:9 设计宽度，两边 letterbox；
- 验收尺寸：
  - 960×720（4:3）
  - 1152×720（16:10）
  - 1280×720（16:9）
  - 1680×720（21:9）
  - 2560×1080 / 3440×1440 全屏
- 检查：无变形/无裁切/鼠标命中正确/相机横向视野增加/面板不重叠。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 4:3 宽度仅 960，菜单/商店文字拥挤 | Phase B 逐屏检查；面板用百分比 + min 宽度；必要时单列 |
| `UI_W` 在纯函数里被直接引用（无 ctx） | 将 `sw` 作为参数传入；或在每帧入口计算一次 `view_size` 传给布局函数，避免全局可变状态 |
| 相机 `base` 从 min 改为 height，垂直 FOV 变化 | 明确“垂直视野恒定”规则；先做 A 阶段手测 |
| 布局测试大量写死 1280 | 测试改为参数化尺寸；新增 4:3/21:9 断言 |
| 超宽屏 HUD 过散 | 设计宽度上限 1680；超过部分 letterbox，不无限拉伸 |
| 与 Steam 大厅/房间 UI 的坐标耦合 | 最后迁移大厅相关屏幕；保留 16:9 回归测试 |

## 4. 需要拍板的细节

1. 4:3 时是否接受“横向看得更少”（固定垂直视野）？——方案 2 默认是。
2. 21:9 以上（32:9）继续 letterbox，还是允许更宽？——建议 letterbox。
3. 设置里是否要加比例预设？——建议加。

## 5. 建议的第一个 commit

- 只改 `ui.rs`（`view_size`/`design_rect`/`mouse_design`）+ `update_camera` + 主菜单/Esc；
- 不改协议、不改模拟；
- `check.ps1` + 4:3/16:9/21:9 布局测试通过后再继续逐屏迁移。
