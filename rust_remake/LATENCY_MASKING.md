# 4.7 延迟掩盖（输入缓冲 + 本地预测 + 乐观/回滚）计划

> 创建 2026-08-15。目标：消除纯 lockstep「host 等齐所有端输入才产帧、谁慢全队卡」的手感瓶颈，
> 让玩家操作在等待权威帧期间也在本地立即上屏（Dota2 手感关键的一半）。
> 前置：网络层已重写为 proto/handshake/lockstep（见 NET_REWRITE.md），4.6 多局配置同步已完成。

## 1. 现状卡点
- 纯 lockstep：client 每帧 `upload` + `step_frame`，**没收到 host 帧就 break 不推进、画面停在等帧**。
- host 等齐 N 端输入才产帧：谁慢/丢包/带宽抖动 → 所有端一起卡。
- 无缓冲、无预测：操作不立即上屏，体感"黏滞"。

## 2. 目标（本次范围）
- **输入缓冲**：client 的输入持续上行（已做）；host 端等齐门槛保留（权威），但用预测掩盖等待。
- **本地预测（乐观推进）**：client 在未收到权威帧时，用**本机输入**推进本地 World，使操作立即上屏；
  收到权威帧后校正。
- **（本阶段 MVP）不做完整回滚重放**：先做「乐观预测 + 收到权威帧直接对齐」的轻量版，
  对纯本机操作（移动/施法，不依赖他人某帧的精确时序）体感改善明显。
  完整回滚重放（他人影响导致分叉时恢复并重放缓存输入）列为后续阶段（见 §6）。

## 3. 改动位置（client，host 不动）
- `client/main.rs` Fighting 的 client 分支：没收到帧时用本机输入乐观推进 world + 扣 accumulator，
  收到权威帧则按权威推进（校正）。
- 需要 `local_player_input`（已有）为每 tick 的预测提供本机输入；其他玩家输入在预测帧里用默认。

## 4. 风险与注意
- 乐观预测的 `world` 是「预测视图」，收到权威帧时可能与预测不一致（他人移动/施法/被打断）。
- MVP 阶段：不一致时直接按权威帧覆盖（可能会有轻微"跳变"，但消除"等帧冻结"）。
- 完整回滚重放（§6）能消除跳变，但需快照缓存 + 输入序列重放，属更高复杂度。

## 5. MVP 验收
- client 未收到帧时画面仍在动（本机操作立即上屏），不再是"等帧冻结"。
- 收到权威帧后世界仍能正常推进、锁步不坏。
- `cargo test --workspace` 全绿（含多局/多端测试）。

## 6. 第二阶段：完整回滚重放（Rollback，待更大范围测试后决定）

**目标**：在阶段一（乐观预测）基础上加回滚：预测与权威帧分叉时恢复权威基准、用缓存输入重放，消除跳变。

### 机制
1. **缓存**：client 保存最近 K tick 的完整输入帧 + `World` 快照（`World: Clone`）。
2. **权威校正**：收到权威 seq 帧 S 时：若预测已到 S 且一致 → 无需回滚；否则恢复「权威帧 S 对应状态」用 S 之后缓存输入按序重放。
3. **重放确定性**：重放用本机输入 + 权威帧已知输入，保证逐位一致。

### 实现要点
- `World` 需可快照/恢复（`Clone` 已足够）。
- 需要「权威 world + 预测 world」双视图：渲染/手感用预测 world（即时），校正用权威 world。
- 缓存 K ≈ 60 tick（1 秒）。回滚只在分叉时触发（低频）。

### ⏳ 决策门：先更大范围测试，再决定是否做
- **现阶段先收集真实手感数据**，不急着实现完整回滚（它是高复杂度、有正确性风险的引擎级特性）。
- 触发条件判断：
  - 若局域网/本地低延迟下「乐观预测 + 跳变」已可接受 → **无需完整回滚**，可把精力转向玩法/属性。
  - 若仍不可接受（如接入 Steamworks 后跨网、抖动增加）→ 再做阶段二，并配自动化回滚测试。
- **自动化基线（已有）**：
  - `lockstep::client_recovers_missing_frame_via_request`（丢帧补发）
  - `host_and_two_clients_sync_over_udp`、`meta_round_sync_keeps_worlds_identical`（多端逐位一致）
  - 阶段二若做，新增：制造「预测走过头 + 权威不同」→ client 回滚重放后与 host 逐位一致。

### 验收（若决定做）
- 自动化测试：预测分叉 → client 回滚重放后与 host 逐位一致。
- 真机多端：无冻结、无显著跳变、锁步不坏。
