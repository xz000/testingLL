# 表现层规划（2026-09-12）

> 前提（PORT_098B_DECISIONS.md D13 / D14）：098c 大量表现是 **war3 引擎局限下的变通**；我们只复刻**信息与手感**，
> 用原生载体呈现。原则：**表现层全部是客户端本地效果，不进快照、不影响确定性**（不改 `PROTOCOL_VERSION`）。
> 关联：`UI_AUDIT.md`（界面清单/缩放）· `JASS_AUDIT_098c.md`（机制真值）。

---

## 1. 目标

1. **信息可读**：伤害/治疗/关键事件在当前 2D 视角下"看得见"。
2. **反馈及时**：命中/击杀/技能就绪有即时视觉与音效反馈。
3. **不破坏确定性**：纯客户端渲染/音频；如需状态（如飘字队列），放客户端字段，不进 `World`。
4. **不照搬 war3**：不引入"漂字多板/贴图法阵"等引擎变通，用原生图形与音效。

## 3. 规划（按价值/成本排序）

### P1 · 飘字与事件提示（纯客户端，价值最高）
- **伤害飘字**：命中时在目标上方浮出数值（098c `ai[]` 头顶点数）；治疗/吸血用绿色、受击用白/红。
- **关键播报上屏**：`Hattrick`（天罚命中 ≥3）、`Vampire`（面具）、`Denied`（弑王反杀）、`First Blood`、连杀
  `Double/Multi/Mega/Ultra/Monster Kill`、`Ludicrous`——098c 是聊天/漂字，我们做成屏幕中上横幅 + 淡出。
- **实现**：客户端 `Vec<FloatText { pos, text, color, life, vy }>`，`update` 推进、`draw_scene` 绘制；
  事件源：比较 `hp` 前后差（需要客户端缓存上帧 hp）或让 `World` 暴露"本帧事件"（**推荐前者，零核心改动**）。
- 成本：中；风险：低。

### P2 · 音效（原生 rodio，零 war3 依赖）
- 发射/命中/爆炸/就绪/倒计时/胜负 6 类音效；用 `rodio` 播放，音量可配。
- 事件源同 P1（客户端比较状态）。
- 成本：中（引入依赖 + 资源 + 一次性触发去重）；风险：低。
- **注**：098c 的 import_5x.mp3 可用，但版权归原项目；建议自制或免版权素材（见 `FONT_LICENSE` 同类合规处理）。

### P3 · 命中/死亡/施法视觉
- 命中闪光、弹体命中火花；死亡淡出圆环 + 残影；施法前摇地面指示（已有瞄准线/AoE 圈，可细化）。
- 柱子被摧毁的碎裂/沙尘（098c `nx=40` 已有 HP 逻辑）。
- 成本：中；风险：低。

### P4 · HUD 增强
- **技能就绪脉冲**（冷却结束瞬间高亮）；施法条（前摇进度条，现为圆环）；
- 状态图标行（Tied/Silenced/Scorched/Slow/Weakened/LavaShield…），把现有 buff 显性化；
- 头像/队伍色（已有）。
- 成本：低-中；风险：低。

### P5 · 相机与可读性
- 跟随自身、目标点标记、出界边缘描边（缩圈预警：下一环倒计时）。
- 成本：低-中；风险：低。

### P6 · 观战/回放（远期）
- 098c 无此概念；但对"帧同步 + 确定性"而言天然可实现（记录输入即可回放）。
- 成本：高；风险：中（需输入录制/回放管线）。

## 4. 实施建议

**批次 1（P1）**：飘字 + 事件横幅（纯客户端）。
- 客户端新增 `float_texts` / `banners` 字段与绘制；事件由"客户端上帧状态对比"推导（hp 下降→伤害飘字；
  `meta` 连杀/播报计数变化→横幅）。
- 加客户端单测（纯函数：事件推导）。

**批次 2（P2）**：音效。
- 引入 `rodio`，音频资源 + 触发去重（同帧同类只播一次）；无声卡时静默降级。

**批次 3（P3+P4）**：命中/死亡视觉 + 状态图标。

**批次 4（P5）**：相机/预警。

---

## 5. 纪律

1. **确定性隔离**：表现层一律"只读 World → 生成客户端效果"；**禁止**把飘字/音效状态写进 `World` 或快照。
2. **跨端一致**：飘字/音效**允许**各端因 fps/音量不同而不完全同步（非模拟状态）。
3. 改了快照/协议才 bump 版本；表现层不应触碰。
4. 每个批次过 `check.ps1`（build+test+clippy，默认与 steam）。
