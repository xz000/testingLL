## 二、我方设计（已定方向）

### 1. 经济组（8 项数值 + 初始金）
**全部开放为自由数值**（房主想怎么设就怎么设）：
`击杀金 / 助攻金 / 胜利金 / 伤害金 / 每轮金` + `击杀/助攻/胜利 点数` + `初始金币`。

> 已实装：默认值对齐 098c（`Qo=20`、`qo=10`、`lo=1`、`Lo=1`、`Mo=2`、`po=1`、`ko/Ko/mo=1/1/2`）；
> 伤害金算法已实现（回合最高伤害者得，含并列）。
> **待做**：把这些从常量变成房间可配项。

### 2. 玩法组

| 项 | 我方设计 | 理由 |
|---|---|---|
| **伤害倍率** | **档位**：75% / 100% / 125% / 150% | 整体改手感，自由数值易调出退化局面；与"回血档位"同构，UI/实现可复用 |
| **击退倍率** | **档位**：75% / 100% / 125% / 150% | 同上 |
| **岩浆伤害** | **档位**：关 / 低 / 标准 / 高 | 同上；"关"= 岩浆不掉血（练习用） |
| **第一轮配置期** | 自由秒数（默认 **40**） | 098c `Uo=40` |
| **局间配置期** | 自由秒数（默认 **30**） | 098c `uo=30` |
| **基础回血** | **档位**（已有）：`0.5/0/0.25/0.75/1.0/2.0` | 已完成 ✅ |
| **场地收缩** | **自由秒数 + 我方模型**（见下） | 098c 是阶跃，我方是连续 —— 参数语义必须按我方重定义 |
| **柱子** | **三态**：关闭 / 随机 / 每局必有 | 原版只能填索引或 0 |
| **冰面** | **三态**：关闭 / 随机 / 每局必有 | 原版绑在 `-league` 里，独立出来 |
| **地图形状** | 暂定**仅圆形**；后续可扩正方形/六边形 | 用户决定 |

#### 场地收缩（我方模型，必须与 098c 区分）

- 098c：**阶跃式**（`wo` = 每多长时间缩一档，离散台阶）。
- 我方：**连续缩小**（`shrink_timer` 到点后按固定速率连续收；测试
  `arena_shrinks_to_zero` / `shrink_is_continuous_after_delay`）。
- **因此参数语义改为**：`收缩延迟秒数`（开局静止期，之后开始缩）+ `收缩总时长秒数`（从开始缩到缩到 0 的时间）。
  比"每玩家多少秒一档"更贴合连续模型，也更好理解。
- 可选：`按玩家数缩放`（人越多缩得越慢/越快）作为**开关**，而不是把系数编进公式。

### 3. 模式开关
- **`-no reward` 等价项**：一个"关闭金币奖励"开关（一键把 5 项金币归零，保留点数）。
- **冰面**：独立三态（不再与联赛模式捆绑）。

## 六、用户裁定（2026-09-12）与依据

### 1. 岩浆：**允许关闭**（与 098c 一致）+ 档位与自定义并存

- **依据**：098c 的设置 1 处理分支（18833–18852）**没有任何下限校验**
  （对比奖励类设置的 `S2I(dd) >= 0`），`set To[i] = S2R(dd)/10` → 输入 0 即"关岩浆"。
- **我方**：档位 `关 / 低 / 标准 / 高`（对应 `0 / 0.5× / 1× / 1.5×`）+ **允许自定义输入**
  （098c 本是自由输入，满足"想多做测试"的玩家）。UI 上"关"标注为"进阶/不推荐"。
- **理由**：既然原版允许，就不该替玩家做决定；但要在 UI 上给出提示。

### 2. 全部数值项：**档位 + 自定义输入并存**

- 伤害/击退倍率：档位 `75% / 100% / 125% / 150%`，**并可自定义输入**（如 200%）。
- 时长类（第一轮/局间配置期、收缩参数）：档位给常用值，**也可自定义秒数**。
- 基础回血：既有档位保留，同样允许自定义。
- 经济类 8 项 + 初始金：**纯自由数值**（无档位）。

### 3. 场地收缩：按 098c 的新调查结论实现 + **需要改我方收缩代码**

**调查结论**（`war3map_pretty.j` 7608/7653 + `sn` 的赋值分布）：

```jass
call TimerStart(Sa, wo*SquareRoot(sn), false, EA)          // 时长 = wo × √sn
call SetTimeOfDayScale($F0/(SquareRoot(sn)*wo))
```

`sn` = **本轮存活人数**（回合重置 `sn=0`；开局逐个 `sn=sn+1`；死亡 `sn=sn-1`；`sn<=1` 判回合结束）。

**我方设计**（连续收缩模型，与 098c 的阶跃不同）：

| 参数 | 含义 |
|---|---|
| `收缩延迟秒数` | 开局静止期，之后开始缩 |
| `收缩基准时长秒数` | **满员时**从开始缩到缩到 0 的时长 |
| 实际时长 | = `基准 × √(存活 / 初始)`（与原版同构：人越少缩得越快） |

**代码影响**：`World` 的收缩逻辑需从"固定速率连续收"改为"按时长换算速率 + 随存活数动态调整"
（现有测试 `arena_shrinks_to_zero` / `shrink_is_continuous_after_delay` 需相应更新，
并**新增**"存活数变化影响收缩速率"的测试）。

### 4. 高级设置徽章（暂定）

大厅列表 + 房间内面板显示：`默认（原版）` / **`自定义 N 项`**（N = 与 098c 默认值不同的项数）。
让玩家一眼看出房主开启了高级设置。

### 5. 改设置 → 全员取消准备（已有基础）

我方已有：
- 配置同步：`host_set_*` 大厅元数据 + `NetCfgSync::HostGather / ClientWait`
- 就绪系统：`ready_state_roundtrip_toggles_withdrawable`（含 withdrawable 语义）

**待做**：
- 新增**配置版本号**（或设置哈希）随元数据广播；任何设置变更即递增
- 各端发现版本变化 → **清空自己的就绪标志**；host 重新进入 gather
- 属**协议/元数据变更**，需 bump `PROTOCOL_VERSION`
- 需测试：host 改设置 → client 的就绪被清（并覆盖"仅表面变化无实质改动"的情形，避免误清）
