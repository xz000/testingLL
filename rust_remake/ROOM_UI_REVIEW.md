# 联机房间 UI 输入梳理（2026-09-13）

> 目的：把 Steam 大厅/房间相关界面的按键（尤其**回车**）梳理成一张“实际代码行为”的表，找出冲突与不一致。
> 本文只做梳理，**未改代码**。发现以 `P#` 编号，末尾给统一方案供选择。
> 代码位置：`client/src/main.rs`（输入）、`client/src/settings_ui.rs`（设置项定义）、`client/src/keys.rs`（键位声明表）。

## 0. 路由（`update` 顶层，先到先得、命中即 return）

| 优先级 | 条件 | 处理函数 | 说明 |
|---|---|---|---|
| 1 | `steam_lobby_pending.is_some()` | 内联 | 连接中（建房/加入异步） |

## 1. 各界面实际按键

### 1.1 连接中（`steam_lobby_pending`）
| 键 | 行为 |
|---|---|
| Esc / Q | 取消，回大厅主界面（`app=MainMenu`, `steam_lobby_menu=true`） |
| 其他 | 忽略（只泵回调） |

### 1.2 房主已离开覆盖层（`steam_host_left_overlay`）
| 键 | 行为 |
|---|---|
| Esc / Q / **Enter** | 关闭覆盖层 → `steam_leave_room()` → 主菜单 |
| 其他 | 忽略 |

### 1.3 房间就绪界面（`steam_lobby_update`，`steam_in_lobby`）
| 键 | 条件 | 行为 |
|---|---|---|
| `I` | `!panel_open && !room_cfg_edit` | 打开好友邀请面板并拉列表 |
| `Q` | `!panel_open && !room_cfg_edit` | 退出房间 |
| `U` | `!locked && !panel_open && !room_cfg_edit` | 切换就绪 |
| `L` | host 且 `!room_cfg_edit`（**未判 panel_open**） | 锁房/解锁 |
| `O` | 在房间内（host 或 client；**未判 panel_open**） | 开/关设置编辑器；关闭时 `publish_room_cfg()` |
| 鼠标点主按钮 | `!panel_open`（**未判 room_cfg_edit**） | = U（host 不满员待启动时 = 启动倒计时） |
| **Enter** | host 且 `underfull_ready && !panel_open && !steam_manual_countdown` | 不满员时启动倒计时 |

### 1.4 好友邀请面板（`steam_friend_list_update`，`panel_open`）
| 键 | 行为 |
|---|---|
| `I` / `Q` | 收起面板（`Q` 第一下只收面板） |
| `R` | 刷新好友 |
| `A` | 打开 Steam 官方邀请窗口 |
| ↑ / ↓ | 选择好友 |
| **Enter** | 邀请选中好友 |

### 1.5 设置编辑器（`room_cfg_editor_input`）——**核心**

列表键（通用）：
- `A/Z/X/C/V`：切分组（`Group::hotkey`）。
- ↑ / ↓：选行。
- ← / →：调值（档位跳变 / 微调；`PlayerLimit` 仅 create 模式可调）。
- `T` 或 **Shift+回车**：编辑当前行（文本行→文本输入；数值行→数值输入）。
- `O` / `Esc`：关闭编辑器（房内=保存并发布；create=取消建房）。

**回车**（同一个键，随“行类型/模式”变化）：

| 行类型 | 示例 | create 模式 | 房内（编辑） | client（只读） |
|---|---|---|---|---|
| 文本输入态（已按过 T） | 房名/备注/数值输入 | **提交输入**（留在编辑器） | **提交输入** | 不可进入 |
| Meta 文本行 | 房间名 / 备注 | **建房** | **无反应**（静默） | 打印“只读” |
| Meta 只读 | 人数上限 | **建房** | **无反应**（静默） | 无反应 |
| 整数行 | 总轮数 / 各经济项 | **建房** | **保存并关闭编辑器** | 打印“只读” |
| 小数行 | 伤害/击退/岩浆倍率、各时长、回血 | **建房** | **保存并关闭编辑器** | 打印“只读” |
| 枚举行 | 地图形状 / 柱子 / 冰面 / 游戏模式 | **建房** | **切换值，不关闭** | 打印“只读” |
| 开关行 | 金币奖励总开关 | **建房** | **切换值，不关闭** | 打印“只读” |

底部提示（`draw_room_cfg_editor`）：
- create：`… T 输入 · 回车 创建房间 · Esc 取消`
- 房内：`… T 或 Shift+回车 输入 · 回车=切换/保存关闭`
- 只读：`… Esc 或 O 关闭`

## 2. 发现的问题

- **P1（核心）回车语义不统一**：开着 O 菜单时，回车可能是「提交输入」「保存并关闭」「切换枚举值」「什么都没发生」四种之一，取决于当前行类型。用户无法预期。底部提示 `回车=切换/保存关闭` 本身就承认了这种二义。
- **P2 create 模式下 Shift+回车被“建房”吞掉**：`edit_key` 含 Shift+回车，但 create 的“回车=建房”判定在行处理之前，所以 create 里 Shift+回车不会进输入态（只有 `T` 可以）。与编辑器注释“两种习惯都支持”不符（create 的底部提示只写了 `T`，但代码层面仍是意外行为）。
- **P3 房名/备注行回车无反应且无提示**：房内编辑时，在 Meta 行按回车静默无事（需 O/Esc 关闭）。
- **P4 人数上限行回车无反应且无提示**：`PlayerLimit` 走 `is_readonly()` 提前 return，连“只读”提示都没有。
- **P5 枚举行 vs 数值行回车后果不同**：数值行回车=关闭编辑器；枚举行回车=切换值仍留在编辑器。同为“行”，行为相反。
- **P6 只读反馈不一致**：client 在多数行回车会打印“只读”，但 `PlayerLimit` 行静默；无 UI 提示，只有日志。
- **P7 `O` 未受 `panel_open` 守卫**：好友面板打开时按 `O` 会在面板后面打开设置编辑器，随后编辑器与面板**同帧都吃键**。
- **P8 鼠标主按钮未受 `room_cfg_edit` 守卫**：编辑器打开时点击主按钮区域会切换“就绪”，与编辑操作抢输入。
- **P9 `L` 锁房未受 `panel_open` 守卫**：面板打开时按 `L` 会直接锁房。
- **P10 提示与实现不完全一致**：房内提示写“回车=切换/保存关闭”，未说清“哪些行会关闭”；create 提示未提 Shift+回车。
- **P11 `room_cfg_editor_input` 的返回值被所有调用方忽略**（`steam_lobby_update` / `steam_lobby_create_update`）：当前无害，但后续若想“编辑器是否吃掉了本帧输入”会需要它。
- **P12 键位声明表未覆盖这些界面**：`keys::keymap()` 只有 `MainMenu/SteamMenu/LobbyList/CreateLobby/Room/...`，且运行时不消费；`SettingsEditor` 的回车多义没有在表里体现。

## 3. 统一方案（已选 B，已实施）

目标：让**回车**在一个界面内语义单一，且与提示一致。

### 方案 A：回车 = 关闭（保存并发布）
- 房内编辑：回车 = 保存并关闭（任何行）。
- 切值/输入只走 `←→` 和 `T`（枚举也可 `←→`）。
- create：回车 = 建房。
- 优点：最符合“回车=确认/关闭”直觉；提示改成 `回车 保存关闭`。
- 缺点：枚举行不能再“回车切换”（部分用户习惯）。

### 方案 B：回车 = 激活当前行（推荐）
- 文本输入态：回车 = 提交（回编辑器）。
- 枚举/开关：回车 = 切换。
- 数值行：回车 = 进入自定义输入（`T` 等价）。
- Meta 文本行：回车 = 进入文本输入（`T` 等价）。
- 只读行：回车 = 明确提示“只读”。
- **关闭统一为 `O` / `Esc`**（保存并发布）。
- create：回车 = 建房（唯一例外，且提示写清）。
- 优点：回车=“操作当前项”，与 O/Esc=“关闭”分工清晰；契合多数玩家“回车去操作/确定”的习惯。
- 缺点：数值行回车从“关闭”改成“进入输入”，老手需适应。

### 方案 C：回车=激活行，Ctrl+回车=关闭
- 与 B 类似，但提供快捷关闭。
- 缺点：Ctrl+回车在 winit 下需额外判定（可行），略显复杂。

**附带统一修复（无论选哪个）**：
- P7/P8/P9：给 `O`、鼠标主按钮、`L` 补 `!panel_open` / `!room_cfg_edit` 守卫。
- P3/P4/P6：只读/无操作行给出**屏幕提示**（复用 `steam_friend_hint` 之类的一行提示），别只打日志。
- P10：把底部提示改成与最终语义一致的一句话。
- P11：让调用方使用返回值或删除返回值（明确契约）。
- P12：把 `Room/SettingsEditor` 的回车语义补进 `keys::keymap()` 文档表。

## 4. 二次核实（2026-09-13 下午）

### 5.1 回车：创建建房 vs 房间内（已逐分支复核）

`room_cfg_editor_input` 的判定顺序（自上而下，先命中先返回）：

1. **文本输入态**（`room_cfg_input` 存在）：回车=提交，**留在编辑器**（两模式相同）。
2. **创建模式 裸回车**：建房（`create_confirm_pending`）；`Shift+回车` 被排除 → 落到第 4 步“操作行”。
3. **创建模式 Esc/O**：取消建房回大厅。
4. **普通态行**：
   - 只读行（client 全部 / host 人数上限）：回车/T → `room_cfg_hint` 提示（不关闭）。
   - 文本行（房名/备注）：回车/T → 进入文本输入。
   - 数值行：回车/T → 进入数值输入。
   - 枚举行/开关行：回车 → 切换值。
5. **关闭**：仅 `O` / `Esc`。

即：“回车=操作当前行”在两个模式下**一致**，唯一差异是创建模式下**裸回车额外担当“建房”**。
（已由源码扫描测试钤住。）

### 5.2 两处文字问题（已修）
- **就绪界面底部提示过期**：原写 `E 编辑房间（含 L 锁定）`，但 `E` 已退休（设置入口统一为 `O`）。
  已改为 host `O 房间设置（含 L 锁定）` / client `O 查看设置`。新增测试 `room_ready_hint_uses_o_not_e_for_settings`。
- **编辑器标题两模式相同**：原均写“房间设置”。已改为创建模式 `创建房间 · 设置`，房间内仍为“房间设置”；
  底部键位提示本就不同（创建：`回车 创建房间`；房内：`回车/T 编辑当前行`）。

### 5.3 场地边界反弹：098c 里到底是什么（结论：**不需要实现**）

深挖 `../098c/out/war3map_pretty.j`：

- 唯一明确写 `-速度×0.5` 反弹的地方是移动收尾的矩形夹取（`8690-8728`）：
  ```jass
  if px>Nr and px<Br then set K[gX]=px
  else  ...夹到边界...; set Q[gX]=-Q[gX]*.5  endif   // X 轴
  // Y 轴同理（br/cr）
  ```
- 而这四个边界在初始化时被设为**整张地图的可玩矩形**（`26640-26646`）：
  ```jass
  set Nr=GetRectMinX(bj_mapInitialPlayableArea)
  set Br=GetRectMaxX(bj_mapInitialPlayableArea)
  set br=GetRectMinY(bj_mapInitialPlayableArea)
  set cr=GetRectMaxY(bj_mapInitialPlayableArea)
  ```
  相机/地图边界是 ±4096（`26126`），而真正对战的**圆形场地**远小于此。
- 场地边缘是**熔岩地形**（可站立，踩上去掉血），不是墙：`7532-7570` 按 `GetTerrainType==qa[ja]` 每 tick 扣 `To[id]`。
  所以玩家可以走出/被击退出圈并被持续扣血，**不会碰到 `RA==6` 的墙而反弹**。

**结论**：098c 里的 `-Q*.5` 反弹只发生在地图可玩矩形的外边界（±4096），在正常对局中根本到不了（熔岩先扣死）；
**场地圆形边界本身没有反弹**，只有掉血。因此**不要**给我们的圆形场地加边界反弹（我们目前“越界掉血”已符合 098c）。
