### 1.2 口径与标记约定

- **不要把不一致直接断言为 bug。** 文档是 **098b tooltip**；Rust 移植按项目既定原则「**行为对齐以 098c 为准，098b 只是草案**」做过校准（见 `skill.rs:41-58`、`:209-211`、`:1286-1290`；`item.rs:174-176` 明示「买价 = war3map_pretty.j 商店训练价」）。
- 三类标记：
  1. `一致` —— 数值吻合
  2. `差异(待确认)` —— 不一致，需人判断按 098b 还是 098c
  3. `缺失` —— 文档有此条目但 Rust 未见实现（或 Rust 有但文档未列，见 §5.2 反向清单）
- 凡 Rust 注释里写明依据（「098c xx」「对齐 098c」）的一律**原文摘录**，用于判断差异是否属有意。

### 1.3 换算口径（必须注意）

- **伤害/时长公式**：文档写 `A + B × 升级次数`，`升级次数 = 等级 − 1` → 文档 L1 = `A`。
  Rust：`SkillGrowth::stats`（`skill.rs:831-848`）为 `实际值 = base + delta × (level − 1)`，
  因此 **文档 `A` 应对应 Rust `*_base`，文档 `B` 应对应 Rust `*_delta`**。
- **冷却序列**：文档给 `30 / 27 / 24.5 / …`，Rust 只存 `cooldown_base`（L1）+ `cooldown_delta`（每级增量）。
  本文档按「文档 L1 值 vs `cooldown_base`」「文档逐档差值 vs `cooldown_delta`」两项分别比对。
- **等级上限**：文档多为 6/7 级；Rust `DefTable::max_level`（`skill.rs:1316-1343`）多为 9/20 级。
  **等级跨度不同 ⇒ 逐档冷却必然不吻合**，这是本次最大系统性差异来源，请重点人工判断。
- **移速**：Rust 内部用「war3 加法值 / 基础 210」的乘数（如 `+200` → `1 + 200/210`），比对时以**加法值**为准。
- 所有 Rust 侧引用均为 `文件:行号`，便于逐条复核。

### 1.4 局限

1. 文档部分数值为 OCR/转录产物，本身带不确定性（文档已自行标注，如「电弧」等级 4 备注处有手写批注）。
2. Rust 侧只比对了**静态数值**（`SkillDef` / `ITEMS` / `Mastery` 常量），**未**比对 `world.rs` 中的运行时结算（KI/FI 击退公式、DoT 均摊、`jn`/`oi` 系数等），这些会放大或掩盖静态差异。
3. 文档中的「装扮/浏览时装」（§文档 564-568）在 Rust 中未找到对应模块，单列于 §5.2。
4. 文档未收录 G 栏位（火球）与 F 栏位（天罚）的 tooltip，这两项只能反向列出（§5.2）。
5. 技能**学习价格**（文档每节的「价格」）原在 Rust 中无对应数据表，现已补齐：
   `SkillId::learn_cost()`（`skill.rs:283`）按文档逐技能取值（11/12/14/15 四档），客户端升级
   与精通购买已改用它。因此下文各表「价格 → 无价格表 / 缺失」的行**应读作「已由
   `learn_cost()` 提供，与文档一致」**；物品买价与精通价格同理已对齐（见 §7.6 / §7.7）。

### 7.5 关于 `xi` 的澄清（影响上方多处「mana」表述）

- 098c 中 **`xi` 不是蓝量**，而是**三精通之一（远程精通 `R00I`）**：
  `kf` 处理器 `Kf=='R00I' → xi[id]=xi[id]+1`，`lf=vi+ei+xi`（三精通之和），
  `Hn` 由 `lf` 缩放，`SetPlayerTechResearched(...,'R017',lf)`。
- 098c 的**蓝量**是 `gn`（`war3map_pretty.j:915-928`：`dX/DX/fX` 把 `gn[id]` 写入
  `UNIT_STATE_MANA`），即**挨打累积的张力值**，用作 `(100+gn)` 放大所受击退；
  **施法不耗蓝**。Rust 的 `Player.mana` 正是此设计（见 `player.rs:215` 注释）。
- 因此：凡把 `bA`/伤害门控描述为「mana(xi) 门控」的说法**不准确**，
  `bA` 的门控 `xi>0` 实为「是否点了远程精通」。

### 7.6 #7 疾风步（与破隐一击相关，待定夺）

文档（098b）与 Rust 现状存在**机制性差异**，非单纯数值差：

- **影袭（A）**：文档「撞向敌人产生伤害 `5.4+0.6×L`，**同时结束隐身**」→ 单笔伤害并解除隐身。
- **潜行（B）**：文档「撞到敌人**不会打断隐身**，并且会**偷取生命** `0.6+0.1×L`」→ 不破隐、改为吸血。
- Rust 现状：A 伤害 `4.6+0.8×(L-1)`（L1=4.6、L6=8.6、L20=19.8）、持续 3.1（文档 2.6）；
  B 速度 100（文档 67）、**生命偷取未实现**。

#### 结论（已解决，2026-09-07）：两份资料**并不矛盾**，差异源于「是否点了远程精通」

098c `bA` 的额外一笔**并非无条件**，而是门控在 `xi[id]>0`（`xi` = **远程精通**，见 §7.5）：

```
function bA:
  local integer id=Vv[nr]
  if xi[id]>0 then                     ← 只有点了远程精通才追加
     if Hr[nr] then SI(nr, 4.6+.8*wr + 5.4+.6*Wr, .6)
     else             SI(nr, 4.6+.8*wr[id], 1)
```

因此：
- **技能说明的「单笔伤害」= 未点远程精通时的基础值**（文档描述的是基础形态，合理）；
- **098c 的额外一笔 = 远程精通带来的加成**（花钱购买的强化）。

**已按 098c 实现**：破隐一击改为 `has_buff(Stealth) && mastery[1] > 0`（`mastery[1]`=远程精通）
才追加一笔同级伤害；未点精通时只有基础单笔伤害，与技能说明一致。
测试 `s010_break_strike_requires_range_mastery` 锁定「无精通=基础 / 有精通≈双倍」。

> 量化参考：此前无条件翻倍使 L1 伤害达 9.2（文档约 5.4~6.0），为文档值的约 **2 倍**；
> 改为精通门控后，未点精通时回到 4.6（与文档差约 10~15%，属可接受范围，暂不调整基数）。

**B 形态（潜行）已实现（2026-09-07）**：疾风步·隐身（B）现挂 `BuffKind::Windwalk(0.6+0.1×L)` buff，
