# 技能/单位状态对齐审计（098c ↔ 我们）

> 起因：`Burnout`（需 `Hr` 燃烧冲刺）与 `Denied`（需 `Fv` 链索绑定）两个播报接不上，
> 怀疑「技能建模没完全对齐」。本文用工具扫出 098c 的**全部按单位/玩家索引的全局数组**并分类，
> 结论是：**真正缺的很少**，绝大多数数组是 War3「傀儡单位」管线的实现细节，我们已用原生模型替代。
>
> 工具：`tools/analyze_098c_state.py`（只读）：
> - 数组模式：`python tools/analyze_098c_state.py Hr Fv nv`（引用数 + set/read 样例）
> - 函数模式（**大小写敏感**）：`python tools/analyze_098c_state.py @AB @WB @mC`（函数体写了哪些状态 + 调了谁）
> 真值：`../098c/out/war3map_pretty.j`。

## 0. 结论（TL;DR）

098c 的按单位/玩家数组可分三类：

1. **War3 傀儡单位管线（实现细节，我们已用原生 `Projectile` 替代，不欠）**：
   `Av`（技能可用性 `id*3+n`）、`hv/jv/Gv`（boolexpr 条件/动作）、`Rv`（傀儡状态 id）、`ev`（傀儡寿命）、
   `Xv/Ev/cv`、`Q/S/U/w/Y/z`（傀儡速度/坐标增量）、`F`（傀儡单位）、`H`（闪电线）。
   → 098c 每次施法都 `CreateUnit` 一个傀儡承载法术；我们用 `Projectile`/区域/即时效果直接表达。**这不是缺口**。
2. **按玩家记账（基本已对齐）**：`Nn/bn`（在场/存活）、`cn/Vv`（队伍/归属）、`Rn`（本轮伤害）、
   `dn/Cn`（连杀计数/时刻）、`Fn`（当前 HP）、`Gn/Hn`（伤害/击退倍率）、`vi/ei/xi/oi/Zr`（等级/成长）。
3. **真·玩法副状态（少量，才是缺口）**：
   - `Hr`（**S012 A 燃烧冲刺**）→ Burnout；**✅ 已建（2026-09-13）**。
   - `Fr/gr`（**S010 A**）/ `fr`（**S010 B**）：带 debuff `gR` 的标记状态；
     **✅ 已核**：`Fr`/`fr`=风步/冲锋隐身（已对齐）；`gr`「招架刷新」与 `CA` 接触伤害分支未对齐（不影响播报）。
   - `kr`（**S012 B 凤凰**瞬时状态）：我们有凤凰实现，**大概率等价**。
   - `Fv` + `Dv/fv/Nv/bv/Bv` + `Mb`：**通用「链接/绑定」系统**（S003/S005/S013/S017B/S019 等都用），
     我们按弹体实现，缺少「单位级绑定」及其交互（Denied）。**结构不同**。

→ **不是「很多技能没对齐」，而是 3 处技能的副状态**：S012 燃烧、S010 标记、通用链索绑定。

## 2. 真·副状态明细（缺口清单）

### 2.1 `Hr` — S012 A 燃烧冲刺（✅ **已实现 2026-09-13**）
- `AB`(S012 A, 11916)：`Hr[ii]=true`、速度 `Q/S/U/w`、寿命 `ev`。
- 交互 `lb`(10961)：`Hr` 单位与**同队**单位接触 → 对队友造成 `Xr=.45√(7+范围精通)`、写「Burn out」、清 `Hr`、速度 ×0.2。
- 我们：已加 `Player.burning`（入快照）+ `CombatEvent::Burnout`；同队接触时对队友造成 `0.45√(7+mastery[1])`、
  熄火（清 burning/control/vel）并播 `ann_burnout` + 「Burn out」漂字。
- 注：098c `wR` 实为「链接谓词」（非距离）；我们以「burning 状态成立」等价处理。单测 `burnout_triggers_on_ally_contact_while_burning`。

### 2.2 `Fr/gr`（S010 A）/ `fr`（S010 B）（❓ 已核：**状态对齐，有细节分歧**）
- `IB`(S010 B, 11890)：`gr[ii]=true; Fr[ii]=true; gR(ii, hR(ii)+Dr/2)`；`RB`(S010 A, 11866)：`fr[ii]=true; gR(...)`。
  （两者都是「给 `ii` 挂 buff + 安排到期回调 `AA`/`DR`」；`fr`/`Fr` 只是「已挂」标志。）
- **已对齐**：`Fr` = 风步/隐身状态 ≈ `Player.windwalk_state` + `BuffKind::Stealth`；
  `fr` = S010 A 冲锋的同名隐身（我们 A 形态也挂 `Stealth` + 踢击窗口，测试 `s010_form_a_charge_vs_b_invisibility`）。
- **未对齐**：
  - `gr` = 「被击中时**刷新风步（招架）**」一次性标志。098c `CA`(7847)：`Fr[nr] and (not Fr[Vr]) and gr[nr]` → 重算 `Xr≤5`、刷新 `Fr`、`gr=false`、
    重排 `AA`(Xr) + `NA`(0.5s 格挡特效)。**我们未建**。
  - `CA`(7847) 接触伤害分支：`fr[nr]` → `4.6+.8*wr`；`Hr[nr]` → `5+.4*Wr`。
    我们 `resolve_player_collisions` 只做了 `stealth_extra`（远程精通门控追加一笔），**公式与 098c 分支不完全一致**。
- 影响：**不影响播报**（S010 无专属音效）。

#### 2.2c S010 B（隐身/风步）与 098c 的机制对照（⚠️ **未对齐**）
形态映射本身是对的：
| 形态 | 098c | 我们 |
|---|---|---|
| A | `RB` → `fr`（冲锋，3.1×jn） | `W098bUtilKind::Charge` |
| B | `IB` → `Fr`+`gr`（隐身，4×jn） | `W098bUtilKind::Windwalk`（`windwalk_state`/`Stealth`） |

但 **B 形态机制不同**：
- **098c B = 隐身 + 被攻击时「招架」**（`CA` 7847）：
  `Fr[nr] and not Fr[Vr] and gr[nr]` → 刷新风步（`Xr≤5s`）、`gr=false`、调度 `NA`（**0.5s 后 `gr=true`**；`AA` 到时清 `Fr/gr`），
  并造成小额互伤 `4.5/(100+gn)` / `2.25/(100+gn)` + 0.5s 格挡特效。
- **我们 B = 隐身 + 接触「吸血」**：`BuffKind::Windwalk(0.6+0.1L)`（`world.rs:3638`），
  注释引用的是**文档/098b 口径**（“偷取生命 0.6+0.1×升级次数”），**在 098c `IB`/`AA`/`CA` 里未找到对应**。
- 结论：**招架（`gr`）我们完全没有；而吸血可能是 098b 遗留** → 与 098c 行为不一致。
- 待决：按 098c 改造 B 形态（招架替掉吸血）还是保留吸血（明确记为有意差异）。

#### 2.2b 若要实现 `gr`/`CA`：影响分析（未开工）
> 先看 §2.2c：这其实是 **S010 B（隐身）机制未对齐** 的一部分。
- `CA`(3746) 挂在**被攻击事件**上（`ni=Condition(function CA)`，16970）：读 `Vr`(攻)/`nr`(受)，`nv[Vr]==1`（英雄）。
  对受方带 `fr`/`Hr`/`Fr`+`gr` 的情况做追加伤害/招架。
- **实现会改什么**：
  1. 「被攻击时」的接触伤害公式：`fr`→`4.6+.8*wr`、`Hr`→`5+.4*Wr`；我们现在只做了 `stealth_extra`。
     → 影响 S010 A/B、S012 A 的接触手感与数值。
  2. `gr` 招架：被攻击时刷新风步（≤5s）+ 小额互伤（`4.5/(100+gn)` / `2.25/(100+gn)`）+ 0.5s 格挡特效。
- **我们侧的障碍**：
  - 我们**没有明确的「英雄近战攻击」事件**——伤害来自弹体/区域/AoE，要在 `damage_player`/`explode_at` 里判定「这次伤害算不算被攻击」并不直观。
  - `gr` 需新增**一次性字段** → 入快照；`CA` 改**伤害逻辑** → 改变世界演化 → 两者都需 **bump `PROTOCOL_VERSION`**。
  - 会动到 `resolve_player_collisions` 与现有单测（`s010_*`、`knockback_scales_*` 等）→ 有回归风险。
- **公式待核**：`wr`/`Wr` 的确切等级来源（可能是 R 槽/E 槽等级）。
- **结论**：低优先级（不影响播报、只影响「风步/冲锋被击时」的细节），建议**暂缓**，仅记录。

### 2.3 `kr` — S012 B 凤凰（✅ **已核：等价**）
- `WB`(S012 B, 12852)：`if not kr[ri]` 才启动 → `kr[ri]=true`（凤凰激活中），安排 `PB` 到期(`3.1*jn[ri]`)；
  `UB` 处理移动指令 → 转向；`kr` 在结束处(12721) 清 `false`。
- **对应我们**：`Player.phoenix_remaining > 0`（`W098bUtilKind::Phoenix` 置 `dur=3.1s`）——
  同样负责「激活窗口 + 移动指令转向 + 风步时发凤凰弹」；到期归零即等价于 `kr=false`。
- 结论：**无需新增字段**。Denied 若实现，`kr` 映射为 `phoenix_remaining > 0`。

### 2.4 `Fv` + 链接族 — 通用「绑定/链接」系统（**结构不同**）
- 写 `Fv` 的技能实现：`Pb`(S003)、`gC`(S005)、`MB`/`pB`(S013)、`CC`(S017B)、`uc/Uc`(S019)、`Mb`（条件）。
- `Mb`(11162)：把 `nr` 绑到**最近敌人** `Fv[nr]=zO`；`aR`(4711) 解绑。
- 「连接规则」谓词：`Dv/fv`（5250 `return nv[gX]==1 or Dv[gX] or fv[gX]`）、`Av/Bv/Nv/bv`（`Mb` 条件 8409–8410）。
- 「Denied」：`mC/qC/QC`（S001/S020/S021 结算）中 `Fv[gX]==ii` 且（岩浆/`kr`/`Fr`）→ `aR(gX)` 断链。
- 我们：用 `ProjectileKind::Chain{last_target}` / Tether 弹体；**无单位级绑定**，故 Denied 交互缺失。
