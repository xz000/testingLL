## 4. 自适应缩放方案（讨论稿）

**问题**：所有界面用绝对像素布局（`draw_text` 字号、面板坐标、行高固定；少量用 `sh*` 比例）。
窗口缩小 / 非 16:9 比例时，固定像素布局会重叠或超界。当前兜底 = 最小窗口 1024×720。

**候选方案**

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 最小窗口（现状）** | 强制 ≥1024×720，布局不变 | 零改动、所见即所得 | 小屏/自由比例受限；不能真正自适应 |
| **B. 逻辑分辨率 + 屏幕坐标** | 固定设计空间 1280×720，`graphics::set_screen_coordinates(0..1280, 0..720)`；布局一律用设计尺寸（不再用 `drawable_size`） | 一次改动，**所有像素内容自动等比缩放**（含字号/线宽）；鼠标命中盒天然对齐 | 需替换 20 处 `drawable_size`；非 16:9 需自行 letterbox，否则拉伸变形；需确认 ggez 鼠标坐标是否随屏坐标变换 |
| **C. 全局缩放系数** | 求 `k=min(sw/1280, sh/720)`，把 `k` 乘进**每个**字号/坐标/行高 | 保留真分辨率（清晰） | 改动面最大（数百处字面量），易漏 |
| **D. 响应式布局** | 每屏按 `sw/sh` 流式排版（比例化所有尺寸） | 最灵活、任意比例好看 | 工作量最大；需逐屏重排与真机打磨 |
| **E. 混合** | B 做底（逻辑空间 + letterbox 保比例），个别屏（学习/商店）再叠加滚动/换行 | 平衡 | 仍需替换 `drawable_size` |

**倾向**：**E（B 为底 + 关键屏滚动兜底）**。
- 逻辑空间取 1280×720；窗口等比缩放 → 所有既有绝对布局自动成立；
- 非 16:9 用 letterbox（黑边）保比例，避免拉伸；
- 学习/商店这类「行数多」的面板保留现有滚动/换行，逻辑空间下也不再拥挤。

**落地要点（若采纳 E）**
1. 新增常量 `UI_W=1280.0 / UI_H=720.0` 与 `fn ui_size()`；把 20 处 `drawable_size()` 换成它。
2. 每屏创建 canvas 后 `canvas.set_screen_coordinates(设计矩形)`（**ggez 0.10 的屏坐标是逐 Canvas 的**，非全局）。非 16:9 时传入 letterbox 后的视口矩形以保比例。
3. **鼠标需手动变换**：`ctx.mouse.position()` 是原始窗口逻辑像素，**不随屏坐标变换**（已核实 ggez 0.10 源码）。需把窗口坐标逆变换到设计空间后再与命中盒比较（封装为 `ui::mouse_design(ctx)` 一处，替换现有命中判定）。
4. 去掉 §2 的最小窗口兜底（或保留更小下限，如 640×360）。
5. 真机在 1024×768、1280×1024、1920×1080、超宽屏各验一遍。

**已核实的关键 API（ggez 0.10）**
- `Canvas::set_screen_coordinates(&mut self, Rect)` / `Canvas::screen_coordinates()` —— **逐 Canvas**。
- `ctx.mouse.position()` 直接返回 `last_position`（窗口逻辑像素），无屏坐标参与。
- `ctx.gfx.drawable_size()` 返回物理像素；逻辑设计空间下应改用它作为布局尺寸。

**风险**：ggez 的屏坐标/鼠标坐标语义需实测确认；letterbox 与「可调整大小」交互需试。
