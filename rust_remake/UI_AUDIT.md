## 4. 自适应缩放（**已实施 E 方案，2026-09-12**）

**问题**：所有界面用绝对像素布局（`draw_text` 字号、面板坐标、行高固定；少量用 `sh*` 比例）。
窗口缩小 / 非 16:9 比例时，固定像素布局会重叠或超界。

**已落地实现**（提交 `71b4b4f`）
- `ui::UI_W=1280.0 / ui::UI_H=720.0`：逻辑设计空间。
- `main.rs` 中 **20 处 `ctx.gfx.drawable_size()` 全部改为设计尺寸**（布局不再依赖物理分辨率）。
- `ui::set_design_coordinates(canvas, ctx)`：每屏建 canvas 后调用；屏坐标矩形 = 兼容窗口比例的**对称外扩矩形**（居中，等价 letterbox，保 16:9 不变形）。调用点：`draw_scene` / `draw_menu` / `draw_steam_connecting` / `draw_steam_host_left_overlay`（其余屏幕复用同一 canvas）。
- `ui::mouse_design(ctx)`：物理像素 → 设计空间逆变换；`main.rs` 中 **15 处 `ctx.mouse.position()` 全部改用它**（含事件循环的鼠标按下/移动与命中盒）。
- 窗口最小尺寸从 1024×720 下调到 **640×360**（缩放已接管，下限仅防呆）。
- 已知：鼠标为**物理像素**（与 `drawable_size` 同基准）——已核实 ggez 0.10 源码 `handle_move(physical_position)`。

**待真机验证**：1024×768 / 1280×1024 / 1920×1080 / 超宽屏 / 全屏 21:9 各验一次（点击命中是否对齐、letterbox 黑边是否正常）。

**方案对比（已选 E）**

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 最小窗口 | 强制 ≥1024×720 | ❌ 只能防坏，不能适配 |
| **B/E. 逻辑分辨率 + 屏坐标（E 已选）** | 固定 1280×720 设计空间；每 canvas 设屏坐标（对称外扩 = letterbox） | ✅ **已实施** |
| C. 全局缩放系数 | 把 k 乘进每个字号/坐标 | 改动面过大 |
| D. 响应式重排 | 每屏按 sw/sh 流式排版 | 工作量大，暂不做 |

**ggez 0.10 关键 API（已核实）**
- `Canvas::set_screen_coordinates(&mut self, Rect)` —— **逐 Canvas**（非全局）。
- `ctx.mouse.position()` 返回物理像素 `last_position`（`handle_move(physical_position)`），**不随屏坐标变换** → 必须手动逆变换。
- `ctx.gfx.drawable_size()` 返回物理像素。

**风险**：ggez 的屏坐标/鼠标坐标语义需实测确认；letterbox 与「可调整大小」交互需试。

### 5.4 追加发现（同轮次，commit 后续）：`draw_text` 居中语义导致 HUD 左半截断

`main.rs` 本地 `draw_text(...)` 的末位参数 `_centered` **被忽略**——函数**始终居中**：

```rust
let dest = Point2 { x: center.x - sz.x / 2.0, y: center.y };  // 与 _centered 无关
```

而 HUD 左上四行是**按左对齐意图**写的 `x = 14.0` → 实际以 14 为**中心**，
文字左半出屏（`模式：死亡竞赛（FFA）` 宽约 136px → 左边缘到 -54px，截断严重）。

**已修**：HUD 四处（金币 / 模式 / 精通 / 进度）与底部「视角」提示改用正确的
`ui::text_left(&mut canvas, ...)`；并在 `draw_text` 上补文档，明确「本函数始终居中，
左对齐请用 `ui::text_left`」，防止再犯。

**同类排查**：全文件扫描「小固定 x + `draw_text`」的调用点，剩余一处
`3129` 行「延迟 XX ms」(x=76) —— 未被截断（x 足够大），且其意向不明确（可能是刻意居中），**未改动**，留待真机确认。

### 5.6 配置界面：页签键与商店买卖（2026-09-12，第四轮）

用户提问三点：① 商店「切换买/卖模式」是否必要？② 配置页用 **F1/F2/F3** 切换、页签却写 `[1]/[2]/[3]`；
③ **J/K/L 是否空闲**？

#### A. 页签键改为 **J / K / L**

**J/K/L 在配置界面内三个键全部空闲**（已用脚本扫描全部 `just(..)`/`char_just(..)` 处理点核实）：

| 键 | 其他界面用途 | 配置界面 |
|---|---|---|
| `J` | 主菜单「加入房间」 | **空闲** ✅ |
| `K` | **全局未使用** | **空闲** ✅ |
| `L` | 房间编辑「锁房」 | **空闲** ✅ |

选它们的理由：三键相邻（家位）、本页空闲、且不与施法键 `c/r/e/d/y/t/f/g`（本页用于选树）冲突。
**F1-F3 保留为等价别名**；`Tab` 仍可循环。
页签标签同步改为 **`[J]技能 [K]商店 [L]成长`**（此前写 `[1]/[2]/[3]`，与实际按键不符）。

#### B. 商店：去掉「买/卖模式」，改**两区并列**

用户直觉（"用买键/卖键"）与 098c 一致 —— 098c 里买（`u000` 商店）与卖（`u005` Sell）本就是**两个入口**。
但**单纯加一个"卖键"解决不了**：列表**内容**随买卖而变（买=每家族下一步，卖=已持有物品）。

故改为**列表两区并列**：

```
[买] 速度之靴 1            5G          ← 每家族下一步（左栏 B/N/M 分类只筛选这一区）
[买] 斗篷 1                4G
[卖] 死亡面具             +10G          ← 持有物品，回收价即 098c `ED` 真值
```

- 数字键 `1..0` **跨区连续编号**，`=`/回车 执行该行（**买或卖由行决定**，不用记模式）
- 新增可点确认行 `[= / 回车] 确认执行选中行（[买] 购买 · [卖] 卖出）`
- 移除了 `V` 模式、`shop_sell_mode` 字段、`LearnAction::ShopToggleSell`
- 修掉两处旧问题：**绘制 11 行 / 输入映射 14 行**（数字键能选中看不见的行）→ 统一 10；
  第 11 项绑在 **`-`** 键（反直觉）→ 去掉
- 切换分类时清空选中（避免「确认」作用到已不可见的行）

**新增共用构造** `MatchApp::shop_rows(me, category)` —— 绘制与键盘选择**共用同一行列表**，
避免此前两处各拼一遍导致的漂移。


### 5.7 单机试验场修复 + HUD 三项（2026-09-12，第五轮）

#### A. **退回主菜单再进 Solo → 金币变成 30**（真 bug，已修）

`reset_to_main_menu()` 用 `MatchState::new(MatchConfig::default(), ..)` 重建 meta
（`default().starting_gold = 20`），而菜单「单机试验场」入口又**直接复用**这份 meta（只切 `app` 状态）→
金币 = 20 + 每轮 10 = **30**（而不是试验场的 9999）。

修法：抽出**唯一**的构造 `fn solo_world_and_meta()`（世界 2 人 + `sandbox` + `starting_gold = 9999`），
`App::new`（Solo/MainMenu 启动）、菜单「单机试验场」、`reset_to_main_menu` **三处共用**；
菜单入口改为**重建**世界/meta（不再复用菜单占位的残留值）。

#### B. 单机试验场**不再计时**（用户提出）

此前：首局配置靠 `pre_game_timer` 兜底自动开始；**局间配置仍走 30s 倒计时**（`tick_learning`）→
试验场会自己跑起来。现改为：沙盒世界/`AppState::Solo`（且非联网）时**完全不计时**，
只用 **空格 / 回车 / P** 手动开始（首局走 `finish_first_round_config`，局间走 `start_next_round`），
学习界面右上角由「剩余 Ns」改为「**自由配置 · 空格 / 回车 开始**」。

### 5.8 「单机仍有购买倒计时」排查结论（2026-09-12）

用户反馈单机试验场**仍有购买倒计时**。排查结果：**代码是对的，跑的是旧二进制**。

证据链：
1. 代码里游戏内唯一的倒计时显示已按沙盒门控：
   ```rust
   let learn_note = if self.world.sandbox { "自由配置 · 空格 / 回车 开始" }
                    else { format!("剩余 {:.0}s", self.meta.learn_remaining.max(0.0)) };
   ```
   且 Learning 分支在沙盒下**提前 return**（不调用 `tick_learning`）→ 既不计时也不倒计时。
2. **`target/release/client.exe` 时间戳是 9/6**（今天所有 UI 改动都不在其中），而它才是
   **带 `client/steam` feature** 的那个（`debug` 是裸 `cargo build`，不带 steam）。
   若以 release 启动，看到的自然是 6 天前的界面（含旧倒计时、旧金币逻辑、旧商店/页签）。

**教训（已修正流程）**：验证"界面是否生效"时先看二进制时间戳与 feature：

```powershell
dir target\debug\client.exe, target\release\client.exe
# release 版需带 feature 重建：
cargo build --release -p client --features client/steam
```

另外本轮还发现并补回了一个**脚本写入丢失**：早前一次"HUD 底板 + 角色提示行"的批量编辑中，
脚本在**替换阶段**断言失败（`let name = if is_me` 缩进不符），而写盘在循环之后 → 两处改动**整体未落盘**。
现已补回，并把脚本改为"全部替换成功后才写文件 + 失败即中止"（避免静默半成品）。
