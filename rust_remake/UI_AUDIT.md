## 4. 自适应缩放（**已实施 E 方案，2026-09-12**）

**问题**：所有界面用绝对像素布局（`draw_text` 字号、面板坐标、行高固定；少量用 `sh*` 比例）。
窗口缩小 / 非 16:9 比例时，固定像素布局会重叠或超界。

**已落地实现**（提交 `71b4b4f`）
- `ui::UI_W=1280.0 / ui::UI_H=720.0`：逻辑设计空间。
- `main.rs` 中 **20 处 `ctx.gfx.drawable_size()` 全部改为设计尺寸**（布局不再依赖物理分辨率）。
- `ui::set_design_coordinates(canvas, ctx)`：每屏建 canvas 后调用；屏坐标矩形 = 兼容窗口比例的**对称外扩矩形**（居中，等价 letterbox，保 16:9 不变形）。调用点：`draw_scene` / `draw_menu` / `draw_steam_connecting` / `draw_steam_host_left_overlay`（其余屏幕复用同一 canvas）。
- `ui::mouse_design(ctx)`：物理像素 → 设计空间逆变换；`main.rs` 中 **15 处 `ctx.mouse.position()` 全部改用它**（含事件循环的鼠标按下/移动与命中盒）。
- 窗口最小尺寸从 1024×720 下调到 **640×360**（缩放已接管，下限仅防呆）。
- 已知：鼠标为**物理像素**（与 `drawable_size` 同基准）——已核实 ggez 0.10 源码 `handle_move(physical_position)`。

**待真机验证**：1024×768 / 1280×1024 / 1920×1080 / 超宽屏 / 全屏 21:9 各验一次（点击命中是否对齐、letterbox 黑边是否正常）。

**方案对比（已选 E）**

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 最小窗口 | 强制 ≥1024×720 | ❌ 只能防坏，不能适配 |
| **B/E. 逻辑分辨率 + 屏坐标（E 已选）** | 固定 1280×720 设计空间；每 canvas 设屏坐标（对称外扩 = letterbox） | ✅ **已实施** |
| C. 全局缩放系数 | 把 k 乘进每个字号/坐标 | 改动面过大 |
| D. 响应式重排 | 每屏按 sw/sh 流式排版 | 工作量大，暂不做 |

**ggez 0.10 关键 API（已核实）**
- `Canvas::set_screen_coordinates(&mut self, Rect)` —— **逐 Canvas**（非全局）。
- `ctx.mouse.position()` 返回物理像素 `last_position`（`handle_move(physical_position)`），**不随屏坐标变换** → 必须手动逆变换。
- `ctx.gfx.drawable_size()` 返回物理像素。

**风险**：ggez 的屏坐标/鼠标坐标语义需实测确认；letterbox 与「可调整大小」交互需试。
